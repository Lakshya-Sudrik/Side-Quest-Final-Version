# SideQuest backend — handoff for the UI merge

This zip is the complete, working backend. It contains no screens. Put the new UI on top of it.

## What's inside
| Path | What it is |
|---|---|
| `backend/` | FastAPI app (`backend/app.py`) — auth, preferences, solo matchmaking, chat, collaborators, listings, trip planner, RAG, gems |
| `src/*.py` | ML + recommender (`recommender.py`, `india_quality.py`, `attractions_model.py`, `safety_index.py`, `youtube_verify.py`, `geo_india.py`, `inference.py`, …) |
| `models/` | Trained models (XGBoost) + RAG embedder |
| `data/` | Runtime data: scored places, geo, safety (crime/police/hospitals), prebuilt ChromaDB index |
| `server.ts` | Express server: serves the Vite UI and proxies `/api/v2/*` to the Python backend (auto-starts it) |
| `src/services/backend.ts` | **Typed API client the UI must use** (all endpoints + TypeScript types) |
| `src/types.ts` | Shared TS types |
| `tests/` | 44 backend tests (`pytest tests -q`) |
| `legacy/README.md` | Old endpoints/files that were retired and what replaced them |

## How to put the UI on top
1. Copy the new UI's `src/` files (components, screens, `App.tsx`, `main.tsx`, `index.css`, assets), plus `index.html`, `public/`, and `vite.config.ts` if it differs, into this folder.
2. **Do not overwrite** `src/services/backend.ts`, `src/types.ts`, or any `src/*.py`. If the UI has its own `types.ts`, merge the two.
3. Every screen should get its data through `api.*` from `src/services/backend.ts`. Don't use mock data (`src/data/mockData.ts` is old). Map each screen like this:
   - Login/Register → `api.login`, `api.register`, `api.options` (the 5 preference questions), `api.me`
   - Home/Gems → `GET /api/v2/gems/city?city=<name>` (or all of India with no city)
   - Routes → `POST /api/v2/gems/route` (5 hidden + 5 famous, each with safety + distance)
   - Trip planner → `api.createPlan`, `api.addStop`, `api.removeStop`, `api.delay` (flight delay), `api.planSuggestions`
   - Solo Match → `api.createTrip`, `api.candidates`, `api.sendRequest`, `api.respond`, `api.requests`
   - Chats → `api.matches`, `api.messages`, `api.send`, `api.block`, `api.report` (chat opens only after both people accept)
   - Collaborator → `api.collaboratorStatus`, `api.uploadDocument`, `api.createListing`; admin → `api.adminCollaborators`, `api.adminVerify`
   - Search bar → `api.ragSearch`
4. If a new UI dependency is needed, add it to `package.json` (keep the existing ones).

## Setup
It ships as two zips. Unzip **both into the same folder**: `part1_code` (code + models) and `part2_data` (the `data/` folder).
```bash
python -m venv .venv && source .venv/bin/activate      # Windows: .venv\Scripts\activate
pip install -r requirements.txt
npm install
python -m backend.rag --build   # REQUIRED once: builds the search index + embedder (~2 min, 83,879 places)
cp .env.example .env        # then fill in the values below
npm run dev                 # http://localhost:3000 (also starts the Python API on :8000)
```
Quick RAG check: `python -m backend.rag --q "quiet waterfall" --city Coorg`
`.env`:
```
YOUTUBE_API_KEY=...          # for the "is this gem real?" YouTube check
DATABASE_URL=                # blank = SQLite at data/app/sidequest.db; or postgresql+psycopg2://user:pass@host:5432/sidequest
SIDEQUEST_ADMIN_EMAILS=you@example.com   # these accounts become admins (verify collaborators)
GEMINI_API_KEY=...           # optional
```

## Check it works
```bash
curl http://localhost:3000/api/v2/health
pytest tests -q              # expect 44 passed
```
Then click through: register → set preferences → Routes (e.g. Bengaluru → Mysuru) → add/remove a stop → apply a 90-min delay → Solo Match with two browsers → accept → chat → collaborator listing.

## Not included (on purpose)
- `node_modules/`, `.env` (secrets), `data/app/` (local test DB + JWT secret; created fresh on first run)
- `data/chroma_db/` and `models/rag_embedder.pkl` (~700 MB): regenerated by `python -m backend.rag --build`
- Raw training dumps (`data/attractions/Review_db.csv`, `_reviews_cache.pkl`, `data/geo/IN.txt`/`IN.zip`): only needed to **retrain** the models. The review snippets the search index uses are pre-extracted in `data/attractions/review_snippets.json.gz`.
